Request path — left to right, one question
1 Browser The question Custom domain for people, workers.dev for API clients. The last 4 exchanges ride along — follow-ups resolve against them.
2 Worker · access.js Checks input + who's asking API key → 2h session → Turnstile, in that order. The first Turnstile pass mints the session — one challenge per visit. Checked before any inference; this is the line where spending starts.
3 AI Gateway → Workers AI Writes SQL qwen2.5-coder-32b, temp 0. Prompt carries today's date + latest season — the model's own "now" is years stale. Repeats served from cache for 0 Neurons.
4 Guard Validates the SQL Allowlist with a preprocessing pass. Strips comments and literals first, then asserts one SELECT. 15 tests.
5 D1 Runs it, returns rows The only source of any figure the user sees. Nothing downstream can alter a number.
6 AI Gateway → Workers AI Describes the rows llama-4-scout-17b, streamed token-by-token. Dates and team names are formatted in code first, so it copies — never converts.
7 Browser Answer + query + rows + chart Streams in as it is written. The prose never appears alone — the reader can always check it against its source.

Reading the colours

Model involved — output untrusted Ground truth — numbers originate Platform — Worker, routing Refusal — stops rather than guesses

Grounding a model in a datastore prevents invented numbers. It does not prevent a wrong query from producing a confidently wrong answer.

"How many MVPs?" once returned 0 — an empty column answers. "Best 3-point season?" answered with overall FG% — a neighbouring column answers. "This past season?" queried 2022-23 — a stale sense of time answers. All real numbers, all confidently wrong; the fix each time was taking the decision away from the model. That is why five of the seven steps can refuse.
